# DroneVision: подробности

Справочное описание отдельных инструментов и методов. Краткое введение — в [README](../README.md).

## Пути, каталог видео и командная строка

Пути не привязаны к компьютеру (`dronevision/paths.py`). Папку с данными программа спрашивает в интерфейсе при первом
запуске и запоминает в `~/.dronevision/settings.json`; если папка потом недоступна, спрашивает снова и не подменяет её молча.
Без явного выбора используется папка `DroneData`, найденная рядом с программой, в домашней папке или на подключённом диске.
Для автоматизации: переменная `DRONEVISION_DATA` важнее выбора в интерфейсе, а файл `dronevision_settings.json`
(образец: `dronevision_settings.example.json`) действует, пока папка не выбрана в интерфейсе. Карта берега берётся из `<папка данных>/maps`, а если её там нет — из `maps/` программы.
Внешние программы ищутся в `bin/`, в корне программы и в `PATH`. Открыть можно любое локальное видео.

Список кейсов на главной странице строится сканированием папки данных (`dronevision/catalog.py`), пары подбираются по именам
и расширениям в любых подпапках: видео `*.MP4/*.MOV`, SRT с тем же именем или номером `DJI_XXXX` (при нескольких кандидатах —
ближайший по дереву папок; пара, найденная далеко от видео, принимается только при совпадении длительности), логи
`*FlightRecord*.txt/.json` где угодно — нужный полёт выбирается по GPS и времени. Тем же индексом пользуется подбор лога
(`discovery.match_log`), когда рядом с видео ничего нет. Названия, тестовые интервалы и проверенные поправки курса
известных роликов подставляются по номеру DJI и дате съёмки.

Повторить сохранённый запуск можно без браузера:

```bash
python -m dronevision mosaic /path/to/project/project.json
```

Новое ядро находится в `dronevision/`: время приводится к UTC, углы интерполируются без скачка на ±180°, высота точки взлёта учитывается отдельно, а кадры обрабатываются потоково без промежуточных PNG.

Модель камеры проверена по береговой линии и движению изображения (подробно — [docs/projection.md](projection.md)):
курс корпуса `osd.yaw` + поправка курса, абсолютные pitch/roll подвеса, FOV Mavic 2 Zoom 66.1° при 24 мм с учётом зума из SRT.
Курс полётного контроллера бывает сбит на 10–15° (особенно после взлёта с судна) — его подбирают для каждого видео:

```bash
python -m dronevision check-sync /path/DJI_XXXX.MP4                  # сдвиг лога, фокусное, скачки курса
python -m dronevision calibrate /path/DJI_XXXX.MP4 --time 30 --time 65 # поправка курса по берегу OSM
```

## Коррекция, GeoTIFF и разметка линий

- Над видео расположены ползунки коррекции: экспозиция, яркость, контраст, гамма, насыщенность, температура. Коррекция видна сразу и применяется к проекции и мозаике.
- В просмотрщике проекции:
  - галочки «Суша» и «Берег»;
  - координаты курсора в метрах и градусах;
  - кнопка «Экспортировать в GeoTIFF» (WGS84 или UTM).
- Инструменты ✎ «Ломаная» и ／ «Отрезок», 10 цветов (объектов):
  - ЛКМ ставит точки, двойной щелчок или ПКМ завершает ломаную;
  - ПКМ по линии открывает меню: профиль RGB и серого, сохранение в TXT (как экспорт транзекты в SNAP), удаление.
- График профилей (под картой) сравнивает несколько отрезков на общей шкале расстояний:
  - «Синхр.» на плашке отрезка: один щелчок по отрезку — совмещение по одной точке (сдвиг, точка = 0 шкалы);
    второй щелчок — по двум точкам (сдвиг и растяжение, обе точки совпадают у всех отрезков; шкала в метрах
    первого открытого двухточечного профиля). Esc / ПКМ после первой точки оставляет одну. Отдельные точки
    меняются и убираются через ПКМ по отрезку.
  - Таблица «профили × каналы» (Общий, R, G, B): клетка включает одну кривую, первый столбец — весь профиль,
    первая строка — канал у всех профилей, «Все» — всё сразу. Наведение на клетку, строку или столбец выделяет
    кривые; щелчок по названию профиля закрепляет выделение; кривая под курсором на графике утолщается.
  - Раскладки: «Вместе», «По профилям» (цвет = канал), «По каналам» (цвет = отрезок). Все линии сплошные.
- Профили сохраняются в `<папка проекта>/profiles/` и берутся из растра без коррекции (`*_data.png`).

## Имена сохраняемых файлов

Все результаты называются одинаково (`dronevision/naming.py`):

`<взлёт>_<имя видео>_<начало видео>_<первое время>s_<последнее время>s_<тип>[_<n>].<расширение>`

- взлёт — первая запись FlightRecord (начало лога), UTC, `ГГГГММДДTЧЧММСС`;
- начало видео — время первого кадра (SRT, без него — creation_time из MP4), UTC, `ГГГГММДДTЧЧММСС`;
- времена — секунды от начала видео с десятыми (`0006.6s`): первый и последний кадр либо начало первого и конец последнего интервала
  (у одиночной проекции оба одинаковые);
- тип: `projection`, `compare1` / `compare2` (пара кадров или пара осреднённых интервалов), `mosaic`, `average`,
  `enhanced`, `currents`, `motion`; у профилей к имени изображения добавляется `lines` или `contours` и имя объекта;
- `_2`, `_3`, … появляется, только если файл с таким именем уже есть: результаты не перезаписываются;
- рядом лежат `*_data.png`, `*.geo.json`, `*_wgs84.tif` / `*_utm37.tif` с тем же именем.

Поправка курса (yaw) и сдвиг часов лога в имя не входят: они записаны в `*.geo.json`
(`yaw_offset_deg`, `log_sync`, `video_start_utc`, `flight_start_utc`, `flight_log`), в JSON течений и в заголовках TXT.

Подробности и план расчёта скорости по двум кадрам: [HANDOFF_tools_2026-09-21.md](../HANDOFF_tools_2026-09-21.md).

## Смещение линий между двумя кадрами

Для ломаных и отрезков одного цвета на двух кадрах (`dronevision/motion.py`) считается, что линия сохраняет форму и только
сдвигается. Из всех сдвигов, одинаково хорошо совмещающих две обводки, берётся кратчайший: для почти прямого слика это
смещение поперёк него (сдвиг вдоль прямой по форме не определяется), для линии с выраженными изгибами изгибы задают и
продольную часть. Длина, число вершин и направление обводки на двух кадрах могут различаться. В строке результата
показано расхождение самих линий после совмещения — если оно сравнимо со смещением, значение грубое.

## Сессии

Состояние работы сохраняется автоматически в `~/.dronevision/last_session.json` и восстанавливается при следующем запуске:
видео, отмеченные кадры и интервалы, поправка курса, дальность, разрешение, коррекция, разметка и последние результаты
(проекция или сравнение, мозаика или осреднение). «Сохранить в файл…» пишет тот же JSON (`*.dvsession.json`) в выбранное место,
«Открыть из файла…» читает его, «Новая сессия» начинает с чистого листа (прежняя остаётся в `previous_session.json`).
Сессия хранит описание результатов, а сами PNG берёт из папки проекта; пути в файле абсолютные, поэтому на другом
компьютере сессия откроется только при тех же путях к видео. Код: `dronevision/session.py`, `web_static/session.js`.

## Выравнивание кадров по изображению

Углы из FlightRecord квантованы по 0.1° и дрейфуют на 1–2° за минуту, при разворотах подвес отстаёт от корпуса: на 1.5–2 км это десятки метров.
Сравнение кадров, мозаика и осреднение поэтому уточняют yaw/pitch/roll каждого кадра по общим деталям (галочка «Выравнивать по изображению», по умолчанию включена).

«Сравнить 2 осреднённых интервала» (`dronevision/interval_compare.py`) — то же, что «Сравнить 2 соседних кадра», но для двух
осреднений: два ближайших к курсору интервала осредняются по отдельности (как «Осреднить выбранный интервал») и кладутся на одну
сетку ENU с одним разрешением. Переключение, разметка, «Рассчитать смещение и скорость», «Повысить разрешение» и экспорт работают
как для пары кадров; время осреднения — среднее время его кадров. Кадры выравниваются внутри каждого интервала; интервалы между
собой — по их средним кадрам и, как и пара кадров, только при видимой суше, чтобы не «съесть» дрейф воды.
Проверка лога по изображению и сохранение поправки синхронизации:

```bash
python -m dronevision check-attitude /path/DJI_XXXX.MP4 --start 20 --end 90 --save   # пишет DJI_XXXX.sync.json
```

Подробности: [HANDOFF_alignment_2026-09-27.md](../HANDOFF_alignment_2026-09-27.md).

## Береговая линия в кадре и выравнивание по ней

Береговая линия — полигоны суши OpenStreetMap (`land-polygons-split-4326`, osmdata.openstreetmap.de, ODbL): самые
подробные из открытых глобальных данных. Планетарный файл (~0.9 ГБ) скачивается один раз и лежит в
`<DroneData>/maps/osm-planet/`; из него автоматически вырезаются небольшие районы вокруг съёмок
(`maps/coast_osm_<З>_<Ю>_<В>_<С>.shp` — те же вырезки едут в zip для Windows). Интернет нужен только для скачивания:

```bash
python -m dronevision coastline                    # скачать (если ещё нет) и нарезать районы всех видео набора
python -m dronevision coastline --at 70.39 58.0    # добавить район вокруг точки
```

После открытия видео (и после каждой перемотки) программа по координатам и углам камеры проверяет, должна ли суша
попасть в кадр, — с учётом кривизны Земли и рефракции, до морского горизонта и немного за него. Если да, об этом пишет
заголовок сворачиваемой плашки «Берег и выравнивание по нему» под видео, а внутри появляется строка:

* **«Наложить береговую линию»** рисует её поверх кадра там, где она должна быть при текущих углах. Линию можно
  перетаскивать по картинке: влево-вправо меняется «Поправка курса», вверх-вниз — наклон камеры (с Shift — точнее).
* **«Выровнять автоматически»**: наклон и крен — по линии морского горизонта (`dronevision/horizon.py`, точность
  ~0.01°), курс — по совпадению суши на карте с тем, что видно ниже горизонта (`dronevision/coastview.py`).
* **«Сохранить выравнивание»** пишет наклон и крен в `<видео>.pose.json` рядом с видео; после этого их учитывают
  проекция, мозаика, осреднение, сравнение и расчёт течений. Курс остаётся в поле «Поправка курса» и в сессии.

Зачем: абсолютный наклон подвеса в логе бывает неверен на градус и больше, курс после взлёта с судна — на 10–20°.
DJI_0531 (Карские Ворота, 18.07.2023): в логе курс 73.5° и наклон −5.7°, по островам у Вайгача и горизонту — 90.9° и −7.0°;
дальности на 1.5 км при этом отличаются на 15 %, а скорости структур — на треть. Старая кнопка «Подобрать курс по берегу»
(урез воды вблизи, до 3.5 км) лежит в той же плашке и тоже работает в любом районе, где есть вырезка.

## Течения и спектр ветровых волн

Кнопка **«Течения и спектр волн»** — отдельный расчёт без параметров, результат в отдельной панели внизу страницы
(`dronevision/wavefield.py`, `web_static/waves.js`). Берётся ближайший выделенный интервал, а без него всё видео
(до 90 с; нужно не меньше 20 с, лучше висение). Считается 1–2 минуты.

Метод: участки поверхности (256×256 точек, шаг сетки выбирается по размеру пикселя на воде) проецируются на плоскость
моря ~7.5 раз в секунду; в трёхмерном спектре яркости энергия ветровых волн лежит на дисперсионной поверхности
`ω = √(g·k) + k·U`, и течение `U` находится её подгонкой (Young et al., 1985; Streßer et al., 2017 — CopterCurrents).
Это течение верхних 0.5–1.5 м (длина волны / 4π), среднее по участку и по записи.

Автоматически делается следующее:

* выбор участков: там, где пиксель на воде не крупнее 2.4 шага сетки, до 12 участков;
* углы камеры каждого кадра — по изображению, если виден морской горизонт: наклон и крен по линии горизонта, дрейф
  курса — по суше или облакам на горизонте (дрейф 0.7° за минуту на 500 м — это ложные 0.1 м/с);
* контроль: расхождение между половинами записи, разброс между участками и **масштаб по дисперсии** — множитель к
  волновым числам, при котором подгонка лучшая. 1.00 значит, что высота и наклон камеры верны; отличие больше 6 %
  выводится как замечание.

В панели: карта с векторами по участкам (зелёные — надёжные), двумерный спектр «куда идут волны», распределения по
длине волны, направлению и частоте, системы волн (направление, длина, период, доля), таблица участков. Файлы — в
`<проект>/waves/`: JSON со всем результатом, CSV с векторами (широта, долгота, составляющие, оценка качества) и
карта PNG с геопривязкой (экспорт в GeoTIFF). Спектры — спектры яркости изображения: длины, периоды и направления
достоверны, уровни энергии относительные; глубина считается большой (для волн короче ~2 глубин это верно).

Проверено на DJI_0531 против ручного расчёта (0.50 м/с на 28°, разброс по 9 участкам 0.03 м/с, масштаб 0.97) и на
синтетическом поле волн с известным течением.
