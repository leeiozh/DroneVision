# Проекция кадра на поверхность воды: проверенная модель

Проверено на DJI_0371 (Mavic 2 Zoom, Белое море, 11.07.2026) независимо от кода приложения:
по береговой линии OSM (`maps/coastline_33_34E_66_67N_land_polygons.shp`), по движению изображения
между кадрами и по фото того же полёта. Затем перенесено на DJI_0323, DJI_0393, DJI_0424.

## Модель камеры (`dronevision/geometry.py`, `dronevision/pose.py`)

| Величина | Источник | Проверка |
|---|---|---|
| Время кадра | абсолютное время первого кадра из SRT + `t` | MP4 `creation_time` округлён до секунды и отстаёт на ~1.6 с — не использовать |
| Сдвиг лога | часы + секунды из `match_log` (GPS SRT ↔ FlightRecord) | по движению изображения: DJI_0371 дополнительный сдвиг 0.00 с (корреляция по pitch 0.988) |
| Часы лога | `flyTime` (ровно 0.1 с на запись), привязанный к медиане `dateTime` | у `dateTime` джиттер ±70 мс и ~6 % дублей миллисекунд |
| Курс камеры | `osd.yaw` (корпус) **+ поправка курса** | `gimbal.yaw` на Mavic 2 имеет произвольный референс: `gimbal.yaw − osd.yaw = −48.5°` весь полёт |
| Pitch | `gimbal.pitch` как есть (абсолютный) | остаток 0.0 ± 0.8° при тангаже корпуса от −6° до +5°; вариант «gimbal + body» неверен |
| Roll | `gimbal.roll` (≈ 0, подвес держит горизонт) | остаток +0.5 ± 1°, от крена корпуса не зависит |
| Фокусное | `f_px = width · focal_len_mm / 31.24` (Mavic 2 Zoom, 4K) | 2957 px по поворотам, 2960 px по шагам подвеса, 2942–2957 px по берегу → HFOV 66.1° при 24 мм |
| Зум | `focal_len` из SRT относительно 24 мм (Zoom) / 28 мм (Pro) | масштаб изображения при 47/48 мм: 1.90/1.99 от ожидаемых 1.96/2.00 |
| Дисторсия | не нужна | подгонка k1 = −0.002 |
| Высота | `osd.height` (от точки взлёта) + высота взлёта над водой | поправка по берегу ≈ +0.7 м |

Поворот: yaw → pitch → roll (Z-Y-X), ENU, камера-пинхол. Проекция — гомография по 4 лучам углов
кадра до плоскости воды; обрезка по горизонту; дальность ограничивается, только если задана.

## Что было не так

1. **FOV 78.8° вместо ~66°** — угловой масштаб завышен на 26 %: проекция сжата к дрону.
2. **Зум `focal / min(focal в ролике)`** — неверно для видео, снятых целиком с зумом
   (DJI_0356 — 31 мм, DJI_0359/0362 — 48 мм, DJI_0423 — 39 мм): FOV ошибался до 2 раз.
3. **Варианты сдвига лога −0.5/−0.9/−1.3 с** — синхронизация уже была верной; при повороте
   10°/с сдвиг 0.9 с даёт 9° ошибки курса.
4. **Мозаика**: `gimbal.yaw` (−48.5°), поворот на курс в обратную сторону, отрицательный масштаб
   луча (разворот на 180°), канвас «север вниз», время от `creation_time`, pitch-only модель.
5. **Курс из FlightRecord сам по себе бывает неверен** — см. ниже. Это не ошибка кода.

## Ошибка курса полётного контроллера

* DJI_0371: в первые 2 с после взлёта с лодки `osd.yaw` меняется на +40.7°, а изображение не
  поворачивается (−0.3°) — контроллер пересчитал курс, отойдя от магнитных помех. Остаточная
  ошибка ≈ **−12°** держится всё висение (кадры 30–120 с на любых курсах, фото DJI_0372/0373),
  а после быстрого пролёта исчезает: фото DJI_0374/0376/0380 совпадают с берегом без поправки,
  курс по GPS совпадает с `osd.yaw` в пределах 0.5°.
* DJI_0393 (14.07): ≈ **+13.6°**; DJI_0323 (09.07): ≈ **−10°**.

Поправка зависит от полёта и его фазы, поэтому это параметр видео (`yaw_offset_deg`), а не константа
камеры. Одиночный кадр даёт её с точностью ±2–3°; берите медиану по 3–5 кадрам с близким берегом.

## Рельефное смещение

С берегом OSM совпадает только **урез воды на берегах, обращённых к камере**. Лес (20–30 м)
и скальные холмы островов при проекции «на уровень моря» заваливаются от камеры: с высоты 232 м
под углом 14° это до сотен метров. Дальние склоны островов поэтому никогда не совпадут с контуром —
это не ошибка ориентации.

## Порядок работы с новым видео

```bash
# 1. синхронизация, фокусное и скачки курса (нужны повороты или наклоны подвеса во фрагменте)
python -m dronevision check-sync /path/DJI_XXXX.MP4
# 2. поправка курса по берегу: кадры с близким берегом, лучше на разных курсах
python -m dronevision calibrate /path/DJI_XXXX.MP4 --time 30 --time 65 --time 99 --out /tmp/heading
```

* `check-sync`: `extra_log_shift_s` должен быть около 0; `focal_px_at_24mm` около 2950 для Mavic 2 Zoom;
  `heading_jumps` — моменты, где курс в логе меняется без поворота картинки (до и после такого
  скачка поправка курса разная).
* `calibrate`: смотрите `quality`, разброс между кадрами и контрольные наложения
  (красное — курс из лога, зелёное — подобранный).
* В web-интерфейсе: «Подобрать курс по берегу» для выбранного кадра, затем «Сделать проекцию».

Не проверено на контрольных данных: профиль Mavic 2 Pro (36 мм экв., HFOV 65.5° — номинал) и кривизна
Земли (на 3 км < 0.3 %, не учитывается).

## Точность углов лога между кадрами (27.09.2026)

По изображению (`check-attitude`, SIFT + перенос через плоскость моря): углы FlightRecord квантованы по 0.1°,
pitch/roll подвеса дрейфуют на 1–2° за минуту, курс корпуса при разворотах расходится с азимутом камеры на 1–2.5°
(follow-сглаживание подвеса), за 200° поворотов накапливается ~6°. Синхронизация DJI_0371 верна (0.00 с),
у DJI_0357 лог отстаёт на 0.11 с (`DJI_0357.sync.json`). Фокусное по самокалибровке вращением 2940 px при 24 мм.
Поэтому кадры между собой совмещаются по изображению (`dronevision/refine.py`), а лог и поправка курса задают
только общую (среднюю) привязку. Подробно: HANDOFF_alignment_2026-09-27.md.
